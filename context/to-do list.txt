- Code edits with an editing tool, not full rewrites. Every coding pass (bug-fix retries, human corrections, a resumed job's redraw) has the coder regenerate the whole matplotlib script, even when one label moves; the rest of the diagram can drift and the reviewers have to re-read everything. Modern harnesses (Claude Code etc.) give the model the current file plus a str_replace/patch-style edit tool and apply small diffs. Do the same: template the last ACCEPTED code into the prompt, have the coder return edits (old -> new snippets), apply them in a Code node, and fall back to a full rewrite only when an edit fails to apply or the change is structural. The whole EDEE harness is behind modern ones in this respect (also: no tools, no file view, history replay instead of a working copy).
